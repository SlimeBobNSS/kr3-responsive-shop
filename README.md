## Практика №12 — адаптивная вёрстка

- На всех пяти страницах есть `viewport`; `responsive.css` подключён после `style.css`.
- Mobile First: одноколоночная мобильная компоновка с расширением через `@media (min-width: ...)`, Flexbox и Grid.
- Адаптированы шапка, навигация, hero, карточки, фильтры, формы, таблица, подвал и модальное окно.
- Изображения не выходят за ширину контейнера (`max-width: 100%`).
- Для hero есть фоновые JPG 480/800/1308 px, выбираемые медиазапросами.
- Для болида RB22 имеются JPEG и WebP по 480/640/739 px; в `product.html` применены `picture`, `srcset`, `sizes`, `width`, `height` и `loading="lazy"`.

## Практика №13 — доступность

- Один `h1` на страницу, семантические `header`, `nav`, `main`, `section`, `aside`, `footer`.
- Ссылка «Перейти к основному содержимому» (`skip-link`), видимый `:focus-visible`.
- Текущий раздел меню обозначен `aria-current="page"`; у кнопки меню используется `aria-expanded` и `aria-controls`.
- Поля форм снабжены связанными `label`; фотографии имеют `alt`, таблица содержит `caption` и заголовки.
- Модальное окно построено на `dialog`, доступно с клавиатуры, закрывается по Escape и имеет ограниченную высоту на мобильных экранах.
- Сообщения о результате демонстрационных форм имеют `role="status"`.

## Проверка

Файлы проекта проверялись в изолированном Chromium на ширинах **360, 430, 768, 1024 и 1440 px** на всех пяти страницах. При этих 25 сочетаниях горизонтального переполнения страницы не выявлено. Дополнительно проверены открытие и закрытие мобильного меню, работа фильтров и сортировки, модального окна и демонстрационных форм. Это **не** Lighthouse-аудит и не подтверждение работы публикации GitHub Pages.

**Lighthouse:** в исходном приложенном ZIP реальных отчётов нет. В существующем GitHub-репозитории ранее опубликованы скриншоты `accessibility-index.png`, `accessibility-catalog.png`, `accessibility-product.png`, `accessibility-order.png`, `accessibility-contacts.png`. Они **не входят в этот ZIP**: перед окончательной сдачей сохраните эти файлы в `lighthouse/` или проведите новый аудит. После правок повторите Lighthouse → Accessibility минимум для `index.html`, `catalog.html` и `order.html`. Баллы для изменённой версии проекта не утверждаются.

**Проверка responsive images:** в DevTools → Network → Img включить `Disable cache`, обновить страницу `product.html`; в Elements проверить `currentSrc`. Выбор ресурса зависит не только от ширины окна, но и от плотности пикселей экрана.

**Сдача:** отправить в СДО ссылку на отдельный репозиторий `kr3-responsive-shop`. Требования практик №12–14 предусматривают оформление изменений через ветки и Pull Request; история Git и фактическая публикация не содержатся в ZIP-архиве.
